## Findings

- The detectors found the seeded failure in every synthetic file and raised nothing on the healthy file.
- `notification_bad_config.log` is only caught by the first-time-error detector: the errors are minutes apart, so they are neither a burst nor a spike.
- The real Hadoop slice is detected as an incident, but the keyword rules label it `application`: Hadoop says "ERROR IN CONTACTING RM" and "NoRouteToHostException", which are not in the network keyword list. Adding `noroute`/`no route to host` to the network keywords (backend's incident builder) would fix it. With an API key, the LLM reads the actual lines and can still name the network cause; the confidence badge then shows "low" because rules and LLM disagree, which is exactly the case it is for.
